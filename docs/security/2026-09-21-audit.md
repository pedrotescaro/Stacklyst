# Stacklyst security and business-logic audit — 2026-09-21

Base: `c87506c` on remote main. Work branch: `security/stacklyst-audit-fixes`.

## Scope and method

Repository-wide inventory and targeted manual tracing covered Next.js route handlers and server/client serialization, Expo session/API/deep-link code, Prisma services/schema/migrations, Supabase identity and permissions, uploads, code execution, configuration, Docker, GitHub Actions and dependencies. Deep review focused on authentication, company/guild ownership, messaging, quizzes/learning rewards, reactions, answers, events and duel evaluation. This is not a line-by-line proof of every file or a production penetration test.

References: [OWASP Top 10](https://top10.owasp.org/), [CWE-639](https://cwe.mitre.org/data/definitions/639.html), [CWE-601](https://cwe.mitre.org/data/definitions/601.html), [CWE-362](https://cwe.mitre.org/data/definitions/362.html), [CWE-200](https://cwe.mitre.org/data/definitions/200.html). Installed Next.js route and data-security guides were read before implementation.

Regression tests accompany each group, including both guild identifiers, unrelated recruiter/user rejection, legitimate access, concurrent claim outcomes, redirect variants, reward reversal, capacity/level/deadline rules, quiz endpoint/feed serialization and client feedback without an initial answer. Mock-based concurrency tests verify transaction/claim contracts; they do not substitute for a live PostgreSQL stress test.

## Remaining concerns and limits

- Web dependency audit reported zero known advisories. Mobile audit reported 12 moderate transitive findings, zero high/critical. npm suggested incompatible Expo/router downgrades; these were not applied. Resolve in a separately validated Expo upgrade, not with `audit fix --force`.
- Gitleaks 8.30.1 scanned 349 historical commits and reported two generic-key candidates in historical `.env.docker.example` / `.env.example` (`JWT_SECRET`, `SEED_DEFAULT_PASSWORD`). No secret values are reproduced here. No findings in current `src`. These historical example values are not proof of active credentials; deployment owners should verify they were never reused and rotate if necessary. History was not rewritten.
- Read-only inspection of the configured PostgreSQL database found many legacy public tables without RLS, but no grants to anon/authenticated/PUBLIC in `information_schema.role_table_grants`. Exposure was not demonstrated. Knowledge graph ownership policies exist; verify effective grants and Data API exposure before enabling direct client access, especially progress/submission writes. No production schema/data was modified.
- Registration deliberately uses an admin-created, pre-confirmed email account when admin credentials exist. Email ownership is therefore not established by this path. Align signup/verification UX and provider email delivery before treating email as verified identity; this audit does not certify that behavior.
- Local rate-limit fallback is per process, registration trusts forwarded headers, CSP permits inline/eval scripts, and several legacy write routes lack consistent payload/rate limits. Infrastructure-aware hardening remains necessary; no production denial-of-service test was performed.
- JWT fallback during transient provider failures cannot provide immediate revocation guarantees. Review session lifetime and outage policy separately.
- Live OAuth, SMTP, storage policies, Redis outage behavior, third-party execution providers, mobile devices and production browser workflows were not exercised. Opt-in database/provider tests are reported as skipped when their required configuration is absent.
- Docker configuration was inspected, but the local Docker daemon was unavailable, so no container build/run was claimed. No dedicated browser E2E suite is configured in the root package scripts.
