0013 [Ttulo1] 2. Objetivo
0014 [] Este documento especifica os 52 casos de uso numerados presentes no projeto stacklyst-seminario.asta, com atores, condições, resultados, fluxos e referências de implementação. Os identificadores UC001 a UC056 são preservados; UC042 a UC045, referentes a comunidades, permanecem como especificações textuais complementares da documentação anterior e não possuem elementos correspondentes no projeto atual. Os diagramas por domínio e as vistas detalhadas foram atualizados a partir desse arquivo Astah, mantendo a visão geral já adotada.
0015 [Ttulo1] 3. Atores do Sistema
0016 [] Ator
0017 [] Natureza
0018 [] Permissões e responsabilidades
0019 [] Visitante
0020 [] Ator humano
0021 [] Cadastra uma conta e faz login antes de acessar as funções protegidas.
0022 [] Usuário autenticado
0023 [] Ator humano
0024 [] Estudante ou desenvolvedor com sessão válida. Estuda, cria ou entra em duelos, interage na comunidade, cria eventos, participa de eventos, consulta vagas e suas notificações. Pode encerrar a própria sessão.
0025 [] Avaliador
0026 [] Ator humano especializado
0027 [] Analisa soluções que exigem avaliação humana após elegibilidade e aprovação administrativa.
0028 [] Administrador
0029 [] Ator humano privilegiado
0030 [] Gerencia permissões, denúncias e candidaturas de avaliador; pode avaliar duelos conforme as regras. Herda as funções do usuário autenticado e pode excluir eventos com autorização administrativa.
0031 [] Recrutador
0032 [] Ator humano especializado
0033 [] Publica vagas e atualiza candidaturas autorizadas. Herda a criação e a participação em eventos do usuário autenticado. O cadastro de empresa pode ser iniciado por qualquer usuário autenticado.
0034 [] Provedor de identidade
0035 [] Sistema externo
0036 [] Valida identidade e sessão via Supabase Auth.
0037 [] Executor externo de código
0038 [] Sistema externo
0039 [] Participa quando executeCode aciona um provedor externo. A execução local em QuickJS é interna ao Stacklyst. Falha de programa difere de indisponibilidade do serviço.

0139 [Ttulo2] 5.1 Caso de Uso UC001 — Cadastrar conta
0140 [] Protótipo de Interface
0141 []  [IMAGEM rId30]
0142 [] Referência visual de UC001. Captura de 07/09/2026.
0143 []
0144 [] Descrição: Criar uma conta individual para acessar funções autenticadas.
0145 [] Tipo: Condução
0146 [] Ator iniciador ou caso chamador: Visitante
0147 [] Atores secundários: Provedor de identidade
0148 [] Pré-condições: Visitante sem sessão autenticada. A disponibilidade do e-mail e do nome de usuário é verificada durante o fluxo.
0149 [] Pós-condições: Identidade e perfil inicial criados; o usuário pode fazer login.
0150 [] Entradas: Username, e-mail, senha e campos opcionais permitidos.
0151 [] Saídas: Confirmação de cadastro ou erros por campo.
0152 [] Fluxo Principal
0153 [] 1. O visitante abre a tela de cadastro e informa os dados solicitados.
0154 [] 2. O Stacklyst valida formato, força da senha e unicidade.
0155 [] 3. O sistema solicita ao serviço de autenticação a criação da identidade.
0156 [] 4. Após confirmação, o Stacklyst cria o registro local e perfil inicial.
0157 [] 5. O sistema confirma o cadastro e direciona o usuário ao acesso apropriado.
0158 [] Fluxos Alternativos
0159 [] • A1 — Dado inválido: o sistema destaca o campo sem criar a conta.
0160 [] • A2 — E-mail ou username existente: o sistema recusa duplicidade.
0161 [] • A3 — Serviço indisponível: o sistema informa falha temporária sem expor detalhes.

0301 [Ttulo2] 5.8 Caso de Uso UC008 — Criar duelo aberto
0302 [] Protótipo de Interface
0303 []  [IMAGEM rId37]
0304 [] Referência visual de UC008. Captura de 12/09/2026.
0305 []
0306 [] Descrição: Disponibilizar um duelo aberto com uma linguagem e um desafio do catálogo, aguardando a entrada de outro usuário. Se já houver uma vaga compatível, o sistema pode iniciar o confronto nessa vaga.
0307 [] Tipo: Condução
0308 [] Ator iniciador ou caso chamador: Usuário autenticado
0309 [] Atores secundários: Nenhum. O segundo participante entra no duelo por meio de UC009.
0310 [] Pré-condições: Usuário autenticado; linguagem suportada e desafio verificável do catálogo.
0311 [] Pós-condições: Duelo aberto no estado PENDING, vinculado ao criador e sem oponente, ou duelo compatível iniciado no estado ACTIVE.
0312 [] Entradas: Linguagem e desafio do catálogo. Não há destinatário a selecionar.
0313 [] Saídas: Identificador do duelo, estado e prazo de espera por participante.
0314 [] Fluxo Principal
0315 [] 1. O usuário abre a área de duelos, solicita criar um duelo e escolhe linguagem e desafio.
0316 [] 2. O sistema verifica a sessão, a linguagem suportada e a existência do desafio no catálogo.
0317 [] 3. O sistema consulta se há uma vaga aberta de outro usuário na mesma linguagem; se houver, segue a alternativa A1.
0318 [] 4. Sem vaga compatível, o sistema registra o usuário como criador de um duelo PENDING, sem oponente, com prazo de espera de até 24 horas.
0319 [] 5. O sistema exibe o duelo aberto. O confronto começa quando outro usuário ocupa a vaga por UC009, com duração de duas horas.

1173 [Ttulo2] 6.1 Decisões adotadas
1174 [] Decisão adotada: O escopo atual abrange aplicação web, aprendizado, gamificação, comunidade, duelos, avaliação humana, eventos, vagas e administração.
1175 []
1176 [] Decisão adotada: A fila atual procura um duelo pendente de outro usuário na mesma linguagem e com vaga disponível, priorizando o mais antigo. Se não houver vaga, cria uma espera. O fluxo atual não usa faixa de XP nem destinatário escolhido.
1177 []
1178 [] Decisão adotada: Resultados duplicados são impedidos por transições condicionais e a recompensa do vencedor é concedida uma única vez; anulação manual exige ação administrativa fora do fluxo automático.
1179 []
1180 [] Decisão adotada: Empresas consultam apenas informações públicas do perfil; e-mail, tokens e dados de sessão permanecem privados.
1181 []
1182 [] Decisão adotada: Lições, exercícios, dicas e respostas canônicas são conteúdos editoriais versionados; não há geração por assistência automatizada externa na versão atual.
1183 []
1184 [] Decisão adotada: O administrador analisa denúncias e pode remover a publicação denunciada; sanções adicionais e recursos não fazem parte da versão atual.
1185 []
1186 [] Decisão adotada: A equipe é formada por Guilherme Alves de Campos, Paulo Henrique Leal dos Santos e Pedro Antonio Silvestre Tescaro; a própria equipe representa o cliente acadêmico do produto.
