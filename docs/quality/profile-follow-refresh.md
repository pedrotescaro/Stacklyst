# Profile follow recommendations and refresh

The profile's personal rail now receives the authenticated viewer ID as a required field. Previously it received only the username, so `WhoToFollow` returned no widget. The viewer is the signed-in user, including when visiting someone else's profile; the viewed profile does not determine recommendations.

Refresh sends `limit` and the IDs currently visible in `exclude`. The server excludes these candidates before gathering and ranking the bounded pools, then reapplies exclusions with the existing self, follow and visibility checks. The API retains its array response for existing clients. Limits are bounded to 1-10 and at most 50 validated IDs; malformed requests return a generic 400 without echoing supplied IDs. No database writes or schema changes were needed.

The widget prevents overlapping refresh clicks, preserves the last list after a failed request, retries with the same refresh exclusions and ignores aborted responses after switching accounts. If no alternatives exist, it keeps the current list and announces that there are no other profiles to suggest. Successful following remains idempotent and refreshes from the server.
